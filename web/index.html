      —

      CoomKit can park your chat model while a big render runs, then bring it straight back.

      KoboldCpp only frees its model in admin mode. Start it with --admin --admindir <folder> and it comes back on the exact config it launched with.

      llama-server only parks in router mode: start it with no -m and point --models-dir at your GGUF folder — one subfolder per model, or loose files. It reloads from its own stored args, so context and offload come back exactly as launched. A classic -m launch can't park; give it --sleep-idle-seconds instead and it parks itself.

        Add remote (OpenAI-compatible)

        Heads up: remote providers see your text. Vision stays local unless you explicitly pick a remote vision model.

        Sync from another CoomKit

        A one-shot clone over your LAN: characters, chats, memories, the gallery — everything. Your local backend settings stay yours. The other install needs "host": "0.0.0.0" in its data/config.json to be reachable, and your current data survives as data.bak/.

        She texts on her own clock

        Normally her unprompted texts are scheduled by this browser tab, which on a phone is suspended the moment the screen blanks. Turn this on and the server keeps her schedule instead — she can text while the app is closed, using the backend and model picked right now. Which threads she may text at all is still the bell toggle on each phone thread. On Termux, run termux-wake-lock or Android will eventually kill the server too.

        A preset bundles a request mode, prompt template, thinking behaviour, sampling and a jailbreak.

        Sampling lives in the scene rail: one set of sliders, not three. Tune it there and hit save into preset.

        System-level framing. On local backends the reasoning prefill in a preset is usually stronger; remote providers strip it, so system text is what you have.

        World info: facts about a setting that get injected when you mention them. A book attaches to a character, to one chat, or to everything — several at once, none of them merged into her card.

        Import a SillyTavern World Info file, or a card that has a lorebook baked into it. I'll tell you what I can't honour before you commit, not after.

          Find/replace rules, run in order. prompt rules change what the model reads; display rules change what you read. Both can be on. Neither ever rewrites the stored message. Your log stays canonical, exactly like macros do.

          Patterns are SillyTavern-style JS literals: /foo/gi — converted to Python. A rule that can't convert is kept and switched off with the reason attached, rather than quietly never firing.
